# Fidelity Rules — 视觉保真迭代方法

复刻/参考驱动的任务在"机制验证通过"之后适用。核心:**机制正确 ≠ 视觉接近**。

## 双关卡验收

1. **机制关**:核心视觉机制可辨识地对应参考(结构、时序、因果)。达标时只允许宣布"机制验证通过",不允许宣布"复刻完成"。
2. **保真关**:逐维度对照,直到"最大的 3 个视觉差距"不再属于可修复范围,或用户确认停止。宣布任何完成度之前必须跑过一轮证据面板(见工具)。

## 每轮迭代的强制动作

1. 生成证据面板:`python3 ~/.claude/skills/creative-rules/scripts/compare_fidelity.py <ref> <ours>`(图片或视频;需 matplotlib,用 anaconda python)
2. 读面板 + 读图,写出**当前最大的 3 个视觉差距**,每个必须标注:
   - 来源分类:A mechanism / B asset / C geometry / D material / E lighting / F camera / G render / H compositing / I temporal
   - 感知影响(占画面面积 × 注视优先级,粗略排序即可)
3. 只修感知影响最大的差距;每轮改动 ≤3 个变量(iteration-rules)
4. **修正路由约束**(防止被"便宜的修正"俘获):
   - 差距来源是 asset/geometry → 禁止调 shader、加 post 来掩盖;要么改资产,要么明确登记为妥协
   - 差距来源是构图/camera → 禁止用 post-processing 补;回到机位/布局
   - 差距来源是 motion/temporal → 禁止用颜色/材质转移注意力
   - 差距来源是 lighting/render(如曝光分布、AgX 压黑)→ 优先渲染端;合成端补救要登记
5. **豁免台账**:MVP 阶段的每项妥协(如"树是简化资产")必须显式登记;机制关通过后**强制重审**台账,逐项决定:修复 / 继续豁免(写理由)/ 用户裁决。禁止静默永久豁免。

## 检查维度(看的清单,非算的清单)

**工具化的 4 项**(人眼最易骗,面板机械呈现):亮度分布(直方图+暗/亮部占比)、边缘/细节密度(全局+分块比值)、尺度分布(元素大小对比)、事件时序(视频:亮度曲线+事件时刻)。

**读图判断的项**:构图/轮廓(silhouette 复杂度)、空间布局、前中后景密度、色彩分布、材质响应(高光/SSS/透射)、边缘特征(硬/软/halo)、景深线索、透视/焦距感、资产保真、渲染特征(噪点/AA)、合成痕迹。

**视频追加**:事件时刻与时长、运动幅度与方向、加减速特征、重复结构、声画同步(astats RMS 包络法,见 reference-reverse-engineer §3.5)。

## 反 Goodhart 纪律

- 不打总分、不用 SSIM/LPIPS 类相似度指标——分数会变成优化目标,面板只提供证据,结论由带上下文的判断做
- 面板数值(如亮部占比)用于**发现差距**,不用于"刷到一致"——分布形状对了但画面不像,以画面为准
- 工具维度按需增补:某次复刻暴露了面板盲区才加,不预建分析器
