# Iteration & Validation Rules — 迭代与验证

## MVP 优先

- 任何效果先做最小闭环:低分辨率、低采样、少节点、粗参数,先跑通再逼近参考。
- 未经用户确认的方案,不许直接跑高成本版本(高分辨率渲染、长序列、大模拟)。
- 每个阶段结束落一个 checkpoint:缓存文件 / 保存工程 / 渲染一帧证据图。

## 验证纪律

- 工具返回 success ≠ 效果正确。视觉里程碑必须截图/渲帧,并且**看图**再下结论。
- 对比验证:把结果图和参考并排比,逐项检查(构图/颜色/材质/运动/层次),列出"已达成 / 有差距 / 未实现"。
- 报告结果时如实:失败说失败并附证据,跳过的步骤明说,不粉饰。

## 失败诊断顺序

1. 先查数据(几何点数/分辨率/通道)再查参数
2. 先查单个节点输出再查整链
3. 参数问题:回到已知可用值,二分逼近
4. 记录每个踩过的坑(症状→原因→修法),沉淀进对应 skill 的 failure-patterns

## 常见视觉质量陷阱(跨软件通用)

- **过度 bloom/glow**:亮部糊成一片。bloom 只该点缀高光,先关掉调对光比再开
- **过度 noise**:噪波叠太多层导致脏。每加一层噪波要说得出它负责什么尺度
- **材质单一**:大面积同 roughness/同色。用遮罩/曲率/位置驱动材质变化
- **画面脏**:对比度不足+颜色浑浊。检查黑位、白位、色彩分离
- **缺层次**:前中后景没有分离。用景深、雾、明度对比、细节密度分层
